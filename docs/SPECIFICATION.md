# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: ИИ-АССИСТЕНТ ДЛЯ УПРАВЛЕНИЯ ЭФФЕКТИВНОСТЬЮ

## 1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

**Название:** Personal AI Effectiveness Assistant

**Цель:** Создать веб-приложение для ежедневного планирования с иерархической системой целей (день → неделя → месяц → квартал → полугодие → год → мечта 5 лет) и автоматической оценкой через Anthropic Claude API.

**Тип приложения:** Локальное веб-приложение (работает на компьютере пользователя)

**Целевой пользователь:** Руководитель компании, который хочет контролировать свою эффективность и движение к долгосрочным целям.

### 2.X. ТЕМА И ВИЗУАЛЬНЫЙ РЕЖИМ (LIGHT/DARK/SYSTEM)

**Режимы темы:**
- `light` — светлая тема
- `dark` — тёмная тема
- `system` — следовать системной настройке (`prefers-color-scheme`)

**Применение темы:**
- Tailwind CSS использует `darkMode: 'class'`
- Источник истины темы — *предпочтение пользователя* (`light|dark|system`)
- Технический механизм — класс `dark` на теге `<html>`

**Приоритеты (multi-user):**
1) Явный выбор темы в профиле пользователя (хранится в БД)
2) Если режим `system` — берётся `prefers-color-scheme`
3) Для незалогиненного пользователя — по умолчанию `system`

**Требование консистентности UI:**
- Компоненты не должны «прибивать» светлые цвета без `dark:*` альтернативы
- Общие блоки (`card`, `input`, `btn-*`) должны использоваться повторно, чтобы тема применялась одинаково на всех страницах

## 3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 3.1. ИЕРАРХИЯ ЦЕЛЕЙ

Пользователь может создавать и редактировать цели для следующих периодов:

1. **Мечта (5 лет)** - одна глобальная цель
2. **Год** - список задач на текущий год
3. **Полугодие** - список задач на текущее полугодие (H1/H2)
4. **Квартал** - список задач на текущий квартал (Q1/Q2/Q3/Q4)
5. **Месяц** - список задач на текущий месяц
6. **Неделя** - список задач на текущую неделю (понедельник-воскресенье)

**Важно:** Задачи для периодов НЕ привязаны к конкретным дням. Это просто список того, что нужно сделать за период.

### 3.2. ЕЖЕДНЕВНОЕ ПЛАНИРОВАНИЕ

**Утром:**
- Пользователь создает план на день (список задач в свободной форме)
- Сохраняется в БД

**Вечером:**
- Пользователь вводит факт выполнения (что реально сделал за день)
- Нажимает кнопку "Получить оценку"
- Система отправляет запрос к Claude API
- Получает оценку и сохраняет в БД

### 3.3. ОЦЕНКА ОТ ИИ

Claude API оценивает день по следующим критериям:

1. **Стратегическое развитие** (1-10)
2. **Операционное управление** (1-10)
3. **Работа с командой** (1-10)
4. **Эффективность времени** (1-10)
5. **Общая оценка** (среднее значение)

**Дополнительно:**
- Текстовая обратная связь (жесткая, конструктивная)
- Анализ выполнения плана vs факт
- **Главное:** Проверка выравнивания (alignment) - работают ли задачи дня на недельные, недельные на месячные, и так далее до мечты

### 3.4. ОТОБРАЖЕНИЕ ALIGNMENT (ВЫРАВНИВАНИЯ)

После оценки показывается цепочка:
```
День → Неделя → Месяц → Квартал → Полугодие → Год → Мечта
```

Для каждой связи ИИ отвечает:
- ✅ Работает (зеленый)
- ⚠️ Частично работает (желтый)
- ❌ Не работает (красный)

С текстовым объяснением почему.

### 3.5. ИСТОРИЯ И АНАЛИТИКА

**Список всех дней:**
- Календарный вид или список
- Каждый день показывает: дату, общую оценку
- Клик на день → детали (план, факт, оценка ИИ)

**График динамики:**
- Линейный график оценок за последние 30/60/90 дней
- Возможность видеть тренд

**Недельный отчет:**
- Агрегация данных за неделю
- Средняя оценка
- Какие недельные задачи выполнены
- Рекомендации ИИ на следующую неделю

### 3.6. НЕЗАКРЫТЫЕ ЗАДАЧИ

**Отдельный раздел:**
- Список задач, которые были в плане, но не выполнены
- Разделение на: стратегические / операционные
- Возможность пометить как "закрыто"

## 4. СТРУКТУРА БАЗЫ ДАННЫХ

### 4.1. Таблица: `dream_goal`
```
id: INTEGER PRIMARY KEY
goal_text: TEXT (цель на 5 лет)
created_at: DATETIME
updated_at: DATETIME
```
**Примечание:** Одна запись - текущая мечта

### 4.2. Таблица: `period_goals`
```
id: INTEGER PRIMARY KEY
period_type: TEXT ('year', 'half_year', 'quarter', 'month', 'week')
period_start: DATE
period_end: DATE
goals_json: TEXT (JSON массив строк)
created_at: DATETIME
updated_at: DATETIME
```

**Пример goals_json:**
```json
[
  "Завершить систему оплаты труда РОП",
  "Согласовать KPI на декабрь",
  "Провести 3 встречи по проекту ЕНКО"
]
```

### 4.3. Таблица: `daily_entries`
```
id: INTEGER PRIMARY KEY
date: DATE UNIQUE
plan_text: TEXT (план на день)
fact_text: TEXT (факт выполнения)
created_at: DATETIME
updated_at: DATETIME
```

### 4.4. Таблица: `evaluations`
```
id: INTEGER PRIMARY KEY
daily_entry_id: INTEGER (FK)
strategy_score: INTEGER (1-10)
operations_score: INTEGER (1-10)
team_score: INTEGER (1-10)
efficiency_score: INTEGER (1-10)
overall_score: REAL (1-10)
feedback_text: TEXT (текст обратной связи)
plan_vs_fact_text: TEXT (анализ план vs факт)
alignment_day_week: TEXT
alignment_week_month: TEXT
alignment_month_quarter: TEXT
alignment_quarter_half: TEXT
alignment_half_year: TEXT
alignment_year_dream: TEXT
recommendations_text: TEXT
created_at: DATETIME
```

### 4.5. Таблица: `open_tasks`
```
id: INTEGER PRIMARY KEY
task_text: TEXT
task_type: TEXT ('strategic', 'operational')
origin_date: DATE
is_closed: BOOLEAN
closed_at: DATETIME
created_at: DATETIME
```

## 5. API ENDPOINTS

### 5.1. Goals API

**GET /api/goals/dream**
- Получить текущую мечту

**POST /api/goals/dream**
- Создать/обновить мечту
- Body: `{ goal_text: string }`

**GET /api/goals/period?type=week&date=2025-11-10**
- Получить цели для периода
- Параметры: type (week/month/quarter/half_year/year), date

**POST /api/goals/period**
- Создать/обновить цели для периода
- Body: `{ period_type: string, period_start: date, period_end: date, goals: string[] }`

### 5.2. Daily Entries API

**GET /api/daily/:date**
- Получить запись за конкретный день

**POST /api/daily**
- Создать/обновить план или факт
- Body: `{ date: date, plan_text?: string, fact_text?: string }`

**GET /api/daily/list?from=2025-10-01&to=2025-11-10**
- Получить список дней за период

### 5.3. Evaluation API

**POST /api/evaluate**
- Отправить запрос к Claude API для оценки дня
- Body: `{ daily_entry_id: number }`
- Система собирает все данные (мечта, периоды, план, факт)
- Отправляет промпт в Claude API
- Сохраняет результат в таблицу evaluations
- Возвращает оценку клиенту

**GET /api/evaluate/:daily_entry_id**
- Получить сохраненную оценку

### 5.4. Open Tasks API

**GET /api/tasks/open**
- Получить список незакрытых задач

**POST /api/tasks/close/:id**
- Пометить задачу как закрытую

### 5.5. Analytics API

**GET /api/analytics/trend?days=30**
- Получить данные для графика (последние N дней)

**GET /api/analytics/week-report?week_start=2025-11-04**
- Получить отчет за неделю

## 6. ПРОМПТ ДЛЯ CLAUDE API

### 6.1. Структура промпта

```
Ты строгий ИИ-ассистент для управления эффективностью руководителя компании.

ИЕРАРХИЯ ЦЕЛЕЙ:

🎯 МЕЧТА (5 лет):
{dream_goal_text}

📅 ЦЕЛИ НА ТЕКУЩИЙ ГОД ({current_year}):
{year_goals}

📆 ЦЕЛИ НА ТЕКУЩЕЕ ПОЛУГОДИЕ ({current_half}):
{half_year_goals}

📊 ЦЕЛИ НА ТЕКУЩИЙ КВАРТАЛ ({current_quarter}):
{quarter_goals}

📋 ЦЕЛИ НА ТЕКУЩИЙ МЕСЯЦ ({current_month}):
{month_goals}

📌 ЦЕЛИ НА ТЕКУЩУЮ НЕДЕЛЮ ({week_dates}):
{week_goals}

---

📝 ПЛАН НА СЕГОДНЯ ({date}):
{plan_text}

✅ ФАКТ ВЫПОЛНЕНИЯ:
{fact_text}

❌ НЕЗАКРЫТЫЕ ЗАДАЧИ ИЗ ПРОШЛОГО:
{open_tasks}

---

ТВОЯ ЗАДАЧА:

1. Оцени день по 4 критериям (1-10):
   - Стратегическое развитие
   - Операционное управление
   - Работа с командой
   - Эффективность времени

2. Рассчитай общую оценку (среднее)

3. Проанализируй план vs факт:
   - Какие задачи выполнены
   - Какие не выполнены
   - Почему

4. ГЛАВНОЕ - проверь alignment (выравнивание):
   - Работают ли задачи сегодня на недельные цели?
   - Работают ли недельные на месячные?
   - Работают ли месячные на квартальные?
   - Работают ли квартальные на полугодовые?
   - Работают ли полугодовые на годовые?
   - Работают ли годовые на мечту?

5. Дай жесткую конструктивную критику (без сахара)

6. Дай конкретные рекомендации на завтра

ФОРМАТ ОТВЕТА - СТРОГО JSON:
{
  "strategy_score": число 1-10,
  "operations_score": число 1-10,
  "team_score": число 1-10,
  "efficiency_score": число 1-10,
  "overall_score": число 1-10 (среднее с точностью до 0.5),
  "plan_vs_fact": "текст анализа",
  "feedback": "жесткая обратная связь",
  "alignment": {
    "day_to_week": "анализ + статус (works/partial/no)",
    "week_to_month": "анализ + статус",
    "month_to_quarter": "анализ + статус",
    "quarter_to_half": "анализ + статус",
    "half_to_year": "анализ + статус",
    "year_to_dream": "анализ + статус"
  },
  "recommendations": "конкретные рекомендации"
}
```

### 6.2. Обработка ответа

- Парсить JSON ответ от Claude
- Сохранить все поля в таблицу evaluations
- Обработать ошибки (если JSON невалидный)

## 8. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 8.1. Производительность
- Страница должна загружаться < 1 секунды
- Запрос к Claude API: таймаут 30 секунд
- БД запросы: < 100мс

### 8.2. Безопасность
- API ключ Anthropic хранится в `.env.local`
- НЕ коммитить API ключ в git
- Все данные локальные (не передаются на внешние серверы кроме Anthropic API)

### 8.3. Надежность
- Обработка ошибок API (если Claude не отвечает)
- Валидация данных перед сохранением в БД
- Резервное копирование БД (опционально)

### 8.4. UX/UI
- Адаптивный дизайн (desktop-first, мобильная версия - nice to have)
- Понятная навигация
- Приятная цветовая схема (не слишком яркая)
- Loader/spinner во время запроса к Claude API

## 13. ДОПОЛНИТЕЛЬНЫЕ ТРЕБОВАНИЯ

- При первом входе показать онбординг
- Предложить создать мечту на 5 лет
- Предложить заполнить цели на год

### 13.2. Подсказки пользователю
- Если не заполнены цели на период (например, квартал), показать уведомление
- Если сегодняшний план не создан, показать напоминание

- Возможность экспортировать всю историю в JSON (опционально)

## 14. КРИТЕРИИ ГОТОВНОСТИ (Definition of Done)

1. Все страницы работают без ошибок
2. Можно создать/редактировать цели всех уровней
3. Можно создать план на день, добавить факт, получить оценку от Claude
4. Оценка корректно сохраняется в БД и отображается
5. Alignment визуализация работает
6. История и аналитика показывают данные
7. Приложение запускается локально одной командой
8. Код задокументирован (комментарии в сложных местах)
