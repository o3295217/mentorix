# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: ИИ-АССИСТЕНТ ДЛЯ УПРАВЛЕНИЯ ЭФФЕКТИВНОСТЬЮ

## 1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

**Название:** Personal AI Effectiveness Assistant

**Цель:** Создать веб-приложение для ежедневного планирования с иерархической системой целей (день → неделя → месяц → квартал → полугодие → год → мечта) и автоматической оценкой через Anthropic Claude API.

**Тип приложения:** Локальное веб-приложение (работает на компьютере пользователя)

**Целевой пользователь:** Руководитель компании, который хочет контролировать свою эффективность и движение к долгосрочным целям.

### 2.X. ТЕМА И ВИЗУАЛЬНЫЙ РЕЖИМ (LIGHT/DARK/SYSTEM)

**Режимы темы:**
- `light` — светлая тема
- `dark` — тёмная тема
- `system` — следовать системной настройке (`prefers-color-scheme`)

**Применение темы:**
- Tailwind CSS использует `darkMode: 'class'`
- Источник истины темы — *предпочтение пользователя* (`light|dark|system`)
- Технический механизм — класс `dark` на теге `<html>`

**Приоритеты (multi-user):**
1) Явный выбор темы в профиле пользователя (хранится в БД)
2) Если режим `system` — берётся `prefers-color-scheme`
3) Для незалогиненного пользователя — по умолчанию `system`

**Требование консистентности UI:**
- Компоненты не должны «прибивать» светлые цвета без `dark:*` альтернативы
- Общие блоки (`card`, `input`, `btn-*`) должны использоваться повторно, чтобы тема применялась одинаково на всех страницах

## 3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 3.1. ИЕРАРХИЯ ЦЕЛЕЙ

Пользователь может создавать и редактировать цели для следующих периодов:

1. **Мечта** - одна глобальная цель (горизонт выбирает пользователь: от 3 месяцев до 10 лет)
2. **Год** - список задач на текущий год
3. **Полугодие** - список задач на текущее полугодие (H1/H2)
4. **Квартал** - список задач на текущий квартал (Q1/Q2/Q3/Q4)
5. **Месяц** - список задач на текущий месяц
6. **Неделя** - список задач на текущую неделю (понедельник-воскресенье)

**Иерархические связи (parentId):** Каждая цель может иметь родительскую цель (`parentId`). Связи создаются автоматически при принятии ИИ-плана с иерархической нумерацией (1. → 1.1. → 1.1.1.) или вручную. Это позволяет отслеживать связь: Мечта → Год → Полугодие → Квартал → Месяц → Неделя.

**Автозавершение:** Когда все дочерние цели одного родителя выполнены, родительская цель автоматически отмечается как завершённая с уведомлением.

**Визуальные связи:** Под текстом дочерней цели отображается метка родительской цели (↑ текст родителя).

**Важно:** Задачи для периодов НЕ привязаны к конкретным дням. Это просто список того, что нужно сделать за период.

### 3.2. ЕЖЕДНЕВНОЕ ПЛАНИРОВАНИЕ

**Утром:**
- Пользователь создает план на день (список задач в свободной форме)
- Сохраняется в БД

**Вечером:**
- Пользователь вводит факт выполнения (что реально сделал за день)
- Нажимает кнопку "Получить оценку"
- Система отправляет запрос к Claude API
- Получает оценку и сохраняет в БД

### 3.3. ОЦЕНКА ОТ ИИ

Claude API оценивает день по следующим критериям:

1. **Движение к мечте** (1-10) — **ГЛАВНАЯ МЕТРИКА**: приблизил ли день к глобальной цели
2. **Стратегический фокус** (1-10) — работа над долгосрочными целями
3. **Продуктивность** (1-10) — выполнение текущих задач
4. **Баланс жизни** (1-10) — здоровье, семья, энергия
5. **Дисциплина** (1-10) — следование плану и привычкам
6. **Общая оценка** (среднее 5 метрик)

**Дополнительно:**
- Текстовая обратная связь (жесткая, конструктивная)
- Анализ выполнения плана vs факт
- **Главное:** Проверка выравнивания (alignment) - работают ли задачи дня на недельные, недельные на месячные, и так далее до мечты

### 3.4. ОТОБРАЖЕНИЕ ALIGNMENT (ВЫРАВНИВАНИЯ)

После оценки показывается цепочка:
```
День → Неделя → Месяц → Квартал → Полугодие → Год → Мечта
```

Для каждой связи ИИ отвечает:
- ✅ Работает (зеленый)
- ⚠️ Частично работает (желтый)
- ❌ Не работает (красный)

С текстовым объяснением почему.

### 3.5. ИСТОРИЯ И АНАЛИТИКА

**Список всех дней:**
- Календарный вид или список
- Каждый день показывает: дату, общую оценку
- Клик на день → детали (план, факт, оценка ИИ)

**График динамики:**
- Линейный график оценок за последние 30/60/90 дней
- Возможность видеть тренд

**Недельный отчет:**
- Агрегация данных за неделю
- Средняя оценка
- Какие недельные задачи выполнены
- Рекомендации ИИ на следующую неделю

### 3.6. НЕЗАКРЫТЫЕ ЗАДАЧИ

**Отдельный раздел:**
- Список задач, которые были в плане, но не выполнены
- Разделение на: стратегические / операционные
- Возможность пометить как "закрыто"

## 6. СИСТЕМА ПРОМПТОВ ДЛЯ CLAUDE API

> **Модель:** Claude через официальный Anthropic SDK endpoint напрямую (без Cloudflare/Wrangler proxy).
> **Промпты хранятся в:** `lib/prompts/` (daily.ts, period.ts, forecast.ts, check-plan.ts, plan-chat.ts, core.ts, types.ts).

### 6.1. Дневная оценка (`lib/prompts/daily.ts`)

**Архитектура:** System prompt (статический, кэшируется) + User prompt (динамический, данные пользователя).

**System prompt** — роль строгого ИИ-коуча с единственной целью: привести пользователя к его мечте.

**Критерии оценки (6 метрик):**

1. **dream_progress_score** (1-10) — **ГЛАВНАЯ МЕТРИКА**: приблизил ли день к мечте
2. **strategic_focus_score** (1-10) — стратегический фокус
3. **productivity_score** (1-10) — продуктивность
4. **life_balance_score** (1-10) — баланс жизни
5. **discipline_score** (1-10) — дисциплина
6. **overall_score** — среднее арифметическое 5 показателей (рассчитывается **СЕРВЕРОМ**, а не моделью; значение из ответа AI игнорируется). Вычисляется функцией `calculateOverallScore()` в `lib/anthropic.ts`

**Вертикальный alignment (6 уровней):**
```
День → Неделя → Месяц → Квартал → Полугодие → Год → Мечта
```
Для каждой связи: `работает / частично / нет` + объяснение.
Гибкий подход: если промежуточные цели не заполнены — фокус на прямую связь День → Мечта.

**Флаги баланса (обязательно):**
- Здоровье: `ok / warning / critical`
- Семья: `ok / warning / critical`
- Энергия: `ok / warning / critical`

**Горизонтальный alignment (опционально, при проблемах):**
- Работа ↔ Здоровье: `баланс / частично / конфликт / критично`
- Работа ↔ Семья
- Работа ↔ Ценности

**Дополнительно:**
- Анализ план vs факт (процент выполнения, невыполненные задачи)
- Жёсткая конструктивная обратная связь (2-3 абзаца)
- 1-2 конкретные рекомендации на завтра
- Предложенные задачи (`suggested_tasks`) — до 3 важных невыполненных задач для трекинга

**Формат ответа — строго JSON:**
```json
{
  "dream_progress_score": 7,
  "strategic_focus_score": 6,
  "productivity_score": 8,
  "life_balance_score": 7,
  "discipline_score": 6,
  "overall_score": 6.8,
  "plan_vs_fact": "анализ выполнения",
  "alignment": {
    "day_to_week": "работает — ...",
    "week_to_month": "частично — ...",
    "month_to_quarter": "работает — ...",

  "suggested_tasks": [
    { "taskText": "...", "taskType": "strategic", "priority": "high", "reason": "..." }
  ]

```

### 6.2. Периодическая оценка (`lib/prompts/period.ts`)

Анализ периода (неделя/месяц/квартал/год) на основе дневных оценок.

**Архитектура:** Средние показатели (по дневным оценкам) рассчитываются **СЕРВЕРОМ** (функция `calculatePeriodAverages()` в `lib/prompts/period.ts`) и подставляются в промпт готовым блоком. ИИ анализирует эти средние и выдаёт текстовый анализ, паттерны, рекомендации (не расчёты).

**Блоки оценки:**
- Профессиональный (strategic_focus/productivity/discipline усреднённо, рассчитано сервером)
- Личный (health/family/energy по 10-балльной шкале)
- Социальный (teamwork)
- Баланс (work-life balance, риск выгорания)

**Дополнительно:** паттерны поведения, тренды, выполнение целей, alignment, блокеры, инсайты (для длительных периодов).

### 6.3. Прогноз (`lib/prompts/forecast.ts`)

ИИ-прогноз достижения целей на основе:
- Базовый период (анализ прошлого: план/факт, completion rate, стратегические задачи)
- Горизонт прогноза (неделя/месяц/квартал/год/мечта)

**Выдаёт:** вероятность выполнения каждой цели, прогноз мечты (estimatedYears, onTrack, gap), сценарии «что если», поведенческие паттерны.

### 6.4. Проверка плана (`lib/prompts/check-plan.ts`)

ИИ анализирует план дня ДО начала работы: соответствие целям, реалистичность, предложения по улучшению.

### 6.5. Чат о плане (`lib/prompts/plan-chat.ts`)

Интерактивный чат с ИИ для обсуждения и доработки плана на день.

### 6.6. Обработка ответа

- Извлечение JSON из ответа Claude (`extractJsonFromAIResponse`)
- Валидация и нормализация оценок (`isValidScore`, `clampScore`)
- Санитизация пользовательского ввода (`sanitizeUserInput`)
- Обработка ошибок при невалидном JSON

## 8. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 8.1. Производительность
- Страница должна загружаться < 1 секунды
- Запрос к Claude API: таймаут 30 секунд
- БД запросы: < 100мс

### 8.2. Безопасность
- **Многопользовательская авторизация:** email + bcrypt-хеш пароля (12 раундов), cookie-сессии
- **HMAC-подпись токенов:** `auth_token` + `auth_token_sig` cookies, верификация в middleware через crypto.subtle (Edge Runtime, без обращения к БД)
- **Верификация email** и **сброс пароля** через токены
- **Шифрование данных at rest (SSE):** AES-256-GCM через Prisma middleware, ~100 текстовых полей в 19 моделях. Ключ: `ENCRYPTION_KEY` (env variable)
- **Аудит-логирование:** автоматический лог всех write-операций (Prisma middleware) + ручной лог auth events
- **Rate limiting:** 5 login/15мин, 3 register/1ч, 10 AI/мин. Блокировка аккаунта после 10 неудачных входов на 30 минут
- API ключ Anthropic хранится в `.env.local` / `.env.production`
- `AUTH_SECRET` — ключ для HMAC подписи сессий
- НЕ коммитить секреты в git
- Санитизация пользовательского ввода перед отправкой в Claude (защита от prompt injection)
- Production на Contabo обращается к Anthropic API напрямую; proxy/baseURL не поддерживаются

### 8.3. Надежность
- Обработка ошибок API (если Claude не отвечает)
- Валидация данных перед сохранением в БД
- Резервное копирование БД (опционально)

### 8.4. UX/UI
- Адаптивный дизайн (desktop-first, мобильная версия - nice to have)
- Понятная навигация
- Приятная цветовая схема (не слишком яркая)
- Loader/spinner во время запроса к Claude API
